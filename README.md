# Hosihikari.Bindings.Endstone

The **Endstone** C++ API surface for the Hosihikari bindings: a CI-generated native-style **Interop** and the native **BindingShim**.

## Boundary

- `Hosihikari.Bindings.Endstone.Interop` is generated by `Hosihikari/Bindings.Generator` from the versioned IR. It mirrors Endstone declarations and keeps `nint`/opaque handles.
- `native/BindingShim/` is the C ABI projection. Endstone plugins resolve the server through `endstone::detail::getServer()`; the shim uses the same bootstrap and calls virtual interfaces directly, so it needs no Endstone import library.
- The hand-written Idiomatic layer is deferred; the generated Interop is the current public surface.

## Current state

- Interop: 205 generated C# files under `src/Hosihikari.Bindings.Endstone.Interop/Generated/`.
- BindingShim: 1,466 functions in `native/BindingShim/generated/win-x64-server/endstone/`.
- Coverage: 319 declarations and 1,831 members bound.

The shim is emitted in `--virtual-dispatch` mode. Inline members, virtual methods (including pure virtual interfaces), eligible template instances, inline/constexpr static fields, and `std::unique_ptr<T>` results are projected; non-virtual out-of-line members remain Interop stubs with a reasoned `NotSupportedException` message. Host-owned interface objects are not disposed; only objects created by the shim receive a disposer.

`NativeMethods.Load(path)` loads the shim. `NativeMethods.GetServer()` returns the host `endstone::Server` handle, which can be wrapped with the generated `Server` class.

## Generate

The frontend parses `include/endstone/endstone.hpp` with the Endstone dependency headers:

```shell
powershell -File ../Generator/frontend/run-endstone.ps1
powershell -File scripts/regenerate.ps1 -IrDirectory ..\Generator\artifacts\endstone-ir
```

## Build

```shell
dotnet build Hosihikari.Bindings.Endstone.slnx -c Release
powershell -File native/BindingShim/build.ps1
```

The native build uses clang-cl, C++20, the MSVC STL, and the expected-lite/nlohmann_json headers already provisioned by the local toolchain. It does not link `endstone_core`; calls dispatch through the host-provided virtual interfaces.

## Generated-source gate

`scripts/verify_generated.py` checks provenance, the coverage baseline, the native table function count, the table version, and the managed table. CI builds the solution, runs the verifier, and validates the committed coverage contract with the generator.
